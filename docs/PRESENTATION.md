## 2 · The Problem

- Engineering, learning and writing now flow through **ChatGPT, Codex, Copilot & CLIs**.
- That usage is **invisible**: nobody knows the spend, the categories, how much shipped code is AI-authored, or whether it's used efficiently & safely.
- Compliance teams have **no forensic guardrails** (PII, license, shadow-AI).

Notes: Frame it as a visibility + governance gap, not a "block AI" story. Non-punitive.

---

## 3 · The Solution

**A governance layer** that turns raw AI telemetry into insight:

- 👤 **Personal** — spend, modes (Plan/Ask/Agent/Skills), categories, efficiency
- 🏢 **Corporate** — org spend, % AI-generated code, department drilldown, budgets
- 🛡️ **Compliance** — anomaly / PII / license / shadow-AI audit + editable risk policies
- 🤖 **AI everywhere** — Claude & ChatGPT insights, streaming assistant, generated runbook

Notes: All employees see the dashboard; compliance manages deep insights & audit.

---

## 4 · Core Metrics (the differentiators)

- **AI Code Ingestion Ratio** — % of committed lines authored by AI vs human
- **Acceptance rate** — accepted vs suggested lines (does AI code survive review?)
- **Prompt efficiency** — iterations-to-resolution (surfaces *waste*, not just volume)
- **Cost-per-outcome** — cost / session, / accepted line, / hour saved
- **Guardrail pass rate** + live **tool risk score**

Notes: These go beyond "$ spent" — they measure whether AI is used *well*.

## 5 · Architecture

```
React 19 + Tailwind v4 + Recharts  ──►  FastAPI (/api/*)  ──►  MongoDB
        (token auth, dashboards)          aggregations         users
                                          Claude / ChatGPT      usage_events
                                          (Emergent LLM key)    alerts / notifications
                                                                connector_policies
```

- JWT email/password auth with role gating (employee vs compliance)
- LLM insights, streaming assistant & runbook via Emergent LLM key
- Daily scheduled budget check (platform cron)

Notes: Everything under `/api`; usage is seeded so demos are never empty.
